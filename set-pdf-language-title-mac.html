How to set the language and title of a PDF on Mac

Updated October 2026, macOS 27.

Two of the most common accessibility problems in PDFs are also among the easiest to fix: a missing document language and a missing title. Here is why they matter and how to set them with the tools you are likely to have on a Mac.

Why they matter

  • Language. Screen readers use the declared language to choose the voice and the pronunciation. Without it, or with the wrong one, a document can become hard to understand: an Italian text read with an English voice is a good example.
  • Title. The title is the first thing a screen reader announces when the document opens. Without it, people hear the file name instead.
  • Window title. A setting called DisplayDocTitle tells PDF viewers to show the title, not the file name, in the window title bar and in the list of open windows. PDF/UA requires it.

Microsoft Word for Mac

  • Title: File > Properties > Title.
  • Language: select the text and choose Tools > Language. Do this for the whole document and for any passages in another language.
  • Export with File > Save As > PDF and “Best for electronic distribution and accessibility”. In our tests this option wrote the title into the XMP metadata and set DisplayDocTitle. Check the language, though: in our test Word declared the interface language instead of the document’s (see Word for Mac declares the wrong language).

Pages

Pages cannot set either. In our tests, its PDF export never declared a document language and never wrote a title into the XMP metadata, and DisplayDocTitle was missing. You need to set them afterwards with another tool. See also why the PDF from Pages is not accessible.

Adobe InDesign

  • Title: File > File Info, then fill in the Document Title.
  • In the Export Adobe PDF dialog, under Advanced, set Display Title to “Document Title”. This sets DisplayDocTitle.
  • Language: set it in your paragraph and character styles (and on any text in a different language), so it is written into the tags.
  • Export with Create Tagged PDF enabled.

Preview

Preview is built on Apple’s PDFKit framework. In our tests, re-saving a tagged PDF with PDFKit kept the existing tags intact, which is good news if you only need to annotate or reorder pages. But PDFKit offers no way to set the document language. It can write a title, but only into the older Info dictionary, not into the XMP metadata that PDF/UA requires, and it does not set DisplayDocTitle.

PDF Accessibility Checker

With the Pro version, the app sets both:

  • It proposes the document language from the text, using Apple’s NaturalLanguage framework.
  • It writes the title into both the Info dictionary and the XMP metadata, and sets DisplayDocTitle.
  • It uses an incremental save: the changes are appended to a copy of the file, so the rest of the document – tags included – stays exactly as it was.
  • The result is a new file named name-accessible.pdf, saved next to the original. The original is never touched.

How we tested

The statements about Word, Pages and PDFKit come from tests we ran in October 2026 on macOS 27 with a fictitious sample document (headings, a list, a table with a header row, two images and a link). The InDesign steps describe the documented settings; we did not include an InDesign export in this test series.
